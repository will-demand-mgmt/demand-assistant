Preferred build: a Copilot Studio agent

This page details the preferred way to realise the intelligence core and agent layers of the architecture. One read-only agent, built in Microsoft Copilot Studio, answers questions about demands and drafts the executive review pack. It stays inside the Microsoft perimeter and reads three sources: A-ah! data through Snowflake, an HLA outcomes record, and SharePoint and Teams content.

Verified so far: Copilot Studio opens with the corporate account, an agent can be created, and the Snowflake connector is in the tool catalogue with three actions. Not yet verified: connection and authentication, policies, licences, the Snowflake schema and its refresh frequency.

Each number beside an amber dot refers to the attention points table below. The agent reaches Snowflake through the Power Platform connector and fixed flows, and writes nothing back.

Use case 1 — Q&A on any demand

Twelve questions cover the day-to-day needs of a demand manager.

  • Status, stage and owner of a demand, and which demands I own
  • Which demands sit too long in a stage, and which wait for IT, Engineering or Operations
  • Priority, rank and target dates; counts per stage and priority
  • Decisions and open action items from the latest meetings
  • The latest BRD, HLA or HLD, and a summary of the requirements
  • What changed on a demand in the last 7 days

Questions on change history, team assignment and requirements text depend on what Snowflake holds (attention point 1).

Use case 2 — Executive Pack

On request, every two weeks or monthly, the agent drafts one card for each of the top 3 or 4 active demands by A-ah! rank, lowest number first.

  1. The demand manager asks for the pack (on request, not scheduled)
  2. A flow reads the active demands by rank and keeps the first 3 or 4
  3. The agent combines status, HLA record, latest minutes and open actions
  4. It drafts each card in English and flags missing HLA outcomes
  5. The demand manager edits the decision text and builds the slides

Each card: rank, name and stage, short status, HLA or HLD result, decision to submit. Schedule changes are decided by people (attention point 11).

HLA outcomes record

One row per demand in a SharePoint list, filled by the demand manager when an HLA arrives.

  • Feasibility; high-level solution definition
  • Effort t-shirt size, per team and overall
  • Cost estimate; requirements coverage %
  • Target design and delivery timeframes

An empty cell shows a missing outcome, and the agent reports it (attention point 8).

Identity and guardrails

Target: end-user credentials, so each person acts with their own permissions. Maker credentials only if IT allows them for the pilot.

  • Web search off; ungrounded answers off
  • Citation in every answer, and a data-as-of line for Snowflake figures
  • Read-only; fixed flows on curated views, no free-form SQL
  • The agent stays unpublished until IT is involved

Pilot path
  1. Measure the time spent preparing the last executive pack
  2. Rank the twelve questions by how often they are asked, and add the real ones
  3. Prototype the Executive Pack in Copilot Studio with three fictitious demands and a fictitious HLA record in SharePoint
  4. Prepare the questions for IT and the Snowflake owner (attention points 1 to 4 and 6)

Gate: no real data is connected until IT has confirmed connection, policies and licences.
